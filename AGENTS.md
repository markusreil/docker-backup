# AGENTS.md

Working rules for this repo (compose-spec project, kopia-only).

- `.env` is hidden and never tracked; `env.example` is the tracked source of
  shape (one pair per compose project: `server/`, and the fixture
  `test/cluster/` whose `.env` is generated by the robot suite, never
  hand-edited). The suite spins up the server from the tracked
  `server/env.test` fixture (local volume, isolated project) — never
  from `server/.env`. Every required var uses `${VAR:?...}` so
  `docker compose config` fails fast.
- No `container_name:`; `restart: unless-stopped`.
- Named volumes for all state; bind mounts only where documented (docker
  socket in the agent, explicit read-only volume mounts, repo volume).
- No `ports:`; the server UI is a variant-agnostic downstream service
  (`VIRTUAL_HOST`, `VIRTUAL_PROTO: https`, `ACME_HOST` plus
  `KOPIA_GEN_SELF_SIGNED_CERT` defaulting to `false`) on the proxy's
  external network, with Homepage labels. Clients bypass the proxy and
  use the backup network directly.
- Images record `BASE_IMAGE` and stamp `BUILD_DATE` at build time
  (`BUILD_DATE=$(date -u +%Y-%m-%dT%H:%M:%SZ) docker compose build`).
- `server/` is the central compose project (own file, own `.env`). It owns
  the `kopia-backup` network by exact name; client clusters join it
  `external: true` after the server is up.
- The agent keeps the backend-agnostic `volumes.yaml` format (template in
  `agent/docker/templates/`): label collection stays decoupled so a
  different backend can be re-added later.
- `CHANGELOG.md` follows Keep a Changelog — add entries under
  `## [Unreleased]` as changes are made.
- Verify with `docker compose config` (per project; include the NFS overlay with NFS vars set when it changes), image builds, and
  `robot -d test/out-kopia test/kopia.robot`.
- Details live in `README.md` and the service READMEs — keep them in sync.
